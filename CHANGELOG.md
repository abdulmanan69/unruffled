## [0.1.0]

First release. Three primitives, implemented, tested and measured. Deliberately small:
everything listed works, and nothing is half-shipped.

### Added

- **`useAction`** — the action lifecycle as one hook. Six machine states so that a fast
  action never flashes an affordance and a slow one never flickers it. The duplicate-submit
  guard is taken synchronously inside the event handler and is keyed by resource, so two
  components writing the same record contend without knowing about each other. Requests abort
  on cancel and on unmount. Automatic retry with jittered backoff and an observable waiting
  state.
- **`useFailure`** — ten failure kinds normalised from RFC 9457, JSON:API pointers,
  `field_errors` maps, flat path lists, bare messages, fetch network errors and aborts. Honest
  `canRetry` and `canRetryNow`, and a live countdown from `Retry-After` in both of its legal
  forms.
- **`useUndoable`** — the deferred write. The interface says "Deleted, Undo" and nothing is
  sent until the window expires, so Undo cancels a request rather than apologising for one
  that already landed. The write survives navigation and unmount; repeats sharing a tag
  coalesce into one commit with a count; `altText` is required by the type, because a toast
  action with no accessible label cannot be reached by keyboard or screen reader.
- **`<Announcer>` and `useAnnounce`** — two live regions, polite and assertive, with a queue
  that spaces writes, drops duplicates inside 500ms and alternates an invisible suffix so a
  repeated message announces at all.
- **`UnruffledProvider`** — optional application-wide defaults for pending policy, retry,
  failure classification and copy.
- **`usePrefersReducedMotion`** — subscribed to the media query rather than snapshotted at
  mount, so turning the preference on mid-session takes effect.
- **Diagnostics** — nine stable `UX####` codes in one table read by the runtime bus and the
  documentation. Four are reported in this release, all from the action machine. Production
  builds contain none of it.
- **`@unruffled/core`** — the framework-agnostic machine runtime and eight injected ports
  (clock, scheduler, storage, navigation, doc, announcer, transport, logger). No framework, no
  globals, no DOM.
- **`@unruffled/testing`** — a fake clock, a recording announcer, scripted navigation, a fake
  document and focus spies, so timed behaviour is asserted rather than slept through.

### Accessibility

- The action trigger is never `disabled`. It stays focusable, reports `aria-disabled` and
  refuses activation in its handlers, so pressing a button does not throw focus to the top of
  the document.
- Keyboard activation is synthesised only for non-button elements, because a native button
  already turns Enter and Space into a click.
- Announcement is on by default; silence is the opt-out. `UX1003` reports a long pending state
  that finished with no live region mounted.

### Measured

- `@unruffled/react` with `@unruffled/core`, everything retained: **8.25 kB brotli**.
- `useAction` alone: 2.08 kB on top of core. `useUndoable`: 1.90 kB. `<Announcer>`: 692 B.
- `@unruffled/core` barrel 5.77 kB, machine runtime 1.49 kB, ports 461 B.
- Zero runtime dependencies in every published package.
- 78 tests, with every timing assertion driven by an injected fake clock.

### Known limits

- ESM only. CommonJS consumers are not supported.
- React 18 and 19 only. No other framework adapter is promised for 1.x.
- Screen-reader verification across NVDA, JAWS, VoiceOver and TalkBack has not been done. The
  suite covers keyboard interaction and ARIA attributes in jsdom.
- Five of the nine diagnostic codes describe primitives that are not in this release and
  cannot fire yet. Their codes are published so the numbering is stable.
